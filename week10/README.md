## 3. 초기 데모 프로토타입 구현 (`테스트` 브랜치 `fire_agent.py`)

데이터의 실제 효용성과 Upstage Solar 연동 흐름을 빠르게 검증하기 위해, CLI 기반의 **대화형 화재 위험 진단 에이전트(`fire_agent.py`)** 1차 데모를 제작해 `테스트` 브랜치에 업로드했습니다.

### 데모 처리 파이프라인
1. **장바구니 변환 (`build_basket`)**
   * `소방청_화재현황_20231231.csv` 115,237건의 각 화재를 장바구니 1개로 변환.
   * 장소(대/중/소), 발화요인·열원, 착화물·연소확대물, 건물 구조·지붕을 범주형 아이템으로 추출하고, 연속형 변수인 발화층(지하/1층/2~3층/4층 이상), 시간대(심야/주간/야간), 계절, 출동도착시간(7분 기준), 습도(<30/30-60/60+), 소방서거리(5km 기준)를 구간화(Binning)하여 아이템화함.
2. **자연어 의도 파악 (`parse_user_intent` — Upstage Solar)**
   * 사용자가 일상 언어로 질문하면(예: *"고깃집에서 불이 크게 나는 조건이 뭐야?"*), Upstage Solar API가 JSON 형태로 `place`(장소 키워드)와 `target`(`property` 재산피해 상위 5% 또는 `casualty` 인명피해)을 추출.
3. **위험 조합 추출 및 답변 생성 (`query_patterns`, `generate_agent_response`)**
   * 필터링된 화재 기록에서 '큰 피해 집단'과 '나머지 집단'의 2~3항목 조합 출현 비율(`sup_heavy / sup_rest`)을 비교해 상위 조합을 뽑고, 이를 Solar에 전달해 근거 수치와 맞춤형 예방 체크리스트를 생성.

## 4. 초기 데모 코드(`fire_agent.py`) 분석 결과 및 문제점

`테스트` 브랜치의 `fire_agent.py`(검토 커밋 `07f855f`)를 검토한 결과, 시연 및 본 개발 전에 반드시 수정해야 할 주요 문제점을 확인했습니다([docs/fire-agent-review.md](../docs/fire-agent-review.md)).

### ① A-Priori / PCY 알고리즘 미구현 (단순 전수 조합 집계)
* **현상**: 코드 주석, CLI 출력, Solar 시스템 프롬프트에는 `A-Priori/PCY 알고리즘`으로 표기되어 있으나, 실제 `query_patterns()`(158~162행)는 아래와 같이 각 장바구니에서 2~3개 조합을 단순 열거하는 **전수 집계(Brute-force Enumeration)** 방식이었음.
  ```python
  for b in heavy_baskets:
      for k in (2, 3):
          for comb in combinations(sorted(b), k):
              c_heavy[comb] += 1
  ```
* **한계**: 교재 6장의 핵심인 **A-Priori 단조성 가지치기($L_1 \to C_2 \to L_2 \to C_3$)**와 **PCY 해시 버킷·비트맵 기반 $C_2$ 후보 압축**이 전혀 적용되지 않았음.
* **개선 방향**: 현재 전수 집계 코드는 검증용 기준선(Baseline)으로 분리하고, 실제 **A-Priori 및 PCY 알고리즘을 직접 구현**하여 동일 지지도에서 빈발 조합·건수 일치 여부와 후보 쌍($C_2$) 절감률을 정량 검증할 예정.

### ② 실행 경로 오류 및 환경 변수 설정 미비
* **현상**: 코드 상단(28행)에는 `.csv.gz` 압축 파일을 자동 선택하는 `DATA_PATH`를 정의했으나, `main()`(279행)에서는 압축 해제된 `DEFAULT_CSV` 경로를 강제 호출하여 저장소를 클론한 직후(`data/소방청_화재현황_20231231.csv.gz`만 존재) 바로 실행되지 않음.
* **개선 방향**: `FireDataset(DATA_PATH)`로 압축 파일 자동 로드를 적용하고, `.env.example` 템플릿 제공 및 `.gitignore`에 `.env` 제외 규칙 추가.
