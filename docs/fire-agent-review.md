# [필수 수정] 실행 경로, 피해 비교 수치, 알고리즘 표기 정리

`테스트` 브랜치의 `fire_agent.py`를 검토하면서 시연 전에 수정할 항목을 정리했습니다.

검토 기준 커밋: `07f855f`

- [ ] **저장소를 받은 상태에서 바로 실행할 수 있게 수정**  
  저장소에는 2023년 데이터가 `.csv.gz`로 올라가 있지만, `main()`은 압축을 푼 `.csv` 경로를 강제로 사용합니다. 이미 구현된 압축 파일 자동 선택을 사용하도록 바꾸고, 새로 받은 저장소에서 실행을 확인합니다. 키 설정을 위해 `.env.example`을 제공하고 실제 `.env`는 Git에서 제외합니다.

- [ ] **피해 비교에서 두 집단의 건수·분모·비율을 함께 표시**  
  현재 수치는 ‘큰 피해 화재 중 해당 조합이 나온 비율’입니다. 출력과 Solar 답변에서 ‘큰 피해 발생 비율’과 ‘위험이 몇 배’라는 표현을 조합 출현 비율에 맞게 수정합니다. 재산피해 기준이 전체 데이터의 95백분위수라는 점을 표시하고, 피해 값이 없는 행과 피해액 0원을 구분합니다. 비교 집단이 비어 있으면 계산을 건너뛰고 안내합니다. 현재 코드에서 비교 집단이 비었을 때 0으로 나누는 오류를 재현했습니다.

- [ ] **알고리즘 표기를 실제 구현에 맞춤**  
  현재는 각 기록의 2~3항목 조합을 열거해 빈도를 세는 방식입니다. 이 구현을 ‘전수 집계’ 기준선으로 남기고, Apriori 가지치기를 구현한 뒤 같은 데이터와 지지도에서 빈발 조합과 건수가 일치하는지 확인합니다. PCY는 해시 버킷과 비트맵 구현이 들어간 뒤 화면과 문서에 표시합니다.

- [ ] **Solar가 질문을 해석하지 못했을 때 분석 범위를 다시 확인**  
  현재는 JSON 파싱에 실패하면 전체 화재의 재산피해 분석으로 넘어갑니다. 장소와 피해 기준을 확인할 수 없으면 사용자에게 다시 묻고, 분석을 실행했을 때는 실제로 적용한 장소와 피해 기준을 결과에 표시합니다.
