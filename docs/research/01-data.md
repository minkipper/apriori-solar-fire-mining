# 1. 데이터 조사: 수집 대상 데이터 정의

> 조사일: 2026-11-04 · 방법: 웹 검색과 공식 페이지 열람 (파일은 내려받지 않음)
> 표기: **확인** = 공식 페이지에서 직접 확인 · **추정** = 설명문으로 미루어 본 것 · **미확인** = 확인하지 못함

## 1.0 결론 요약

| 번호 | 수집 대상 | 필요도 | 확보 가능성 | 상태 |
|---|---|---|---|---|
| 1.1 | 화재 발생 건별 데이터 | 필수 | 높음 | CSV 공개 확인, 건 단위 여부는 추정 |
| 1.2 | 기상 데이터 | 필수 | 높음 | API 확인, 실효습도는 포털 제공 화면 확인 |
| 1.3 | 건축물 데이터 | 선택 | 낮음 | API는 있으나 화재 데이터와 결합 키가 없음 |
| 1.4 | 비정형 텍스트 (경위서) | README상 필수 | 매우 낮음 | 공개 데이터에서 확인되지 않음 |
| 1.5 | 코드표·분류체계 | 필수 | 중간 | 분류 구조만 확인, 현행 코드표 원문은 미확인 |

**데이터 사용 가능 여부:** 1.1 + 1.2 + 1.5로 장바구니 모델은 성립할 가능성이 높다. 1.4가 없으면 README의 Stage 1(Solar 태그 추출)은 현재 형태로 성립하지 않는다. 1.1의 행 수와 `일시` 형식을 파일로 확인해야 최종 확정된다.

## 1.1 화재 발생 건별 데이터 (필수)

**프로젝트에서 쓰이는 곳:** 장바구니 1개 = 화재 1건. 발화 원인, 장소, 시간, 피해 규모가 아이템이 된다.

### 1.1.1 소방청_연간화재통계 (주 후보)

- 출처: [data.go.kr 15060386](https://www.data.go.kr/data/15060386/fileData.do)
- 제공: 소방청 화재대응조사과 · CSV · 연 1회 갱신 · 수정일 2025-11-18 · 이용허락 제한 없음 (**확인**)
- 건 단위 여부: 설명에 "각 화재별 인명 피해자 및 재산 손해"가 있음 (**추정**)
- 행 수, 수록 기간, 로그인 필요 여부: **미확인**

| 그룹 | 컬럼 (페이지 기준 17개) | 아이템 후보 |
|---|---|---|
| 시간 | 일시 | 계절, 요일, 시간대 (시각 포함 여부 **미확인**) |
| 장소 | 시도, 시_군_구, 장소 대/중/소분류 | 장소 유형, 지역 |
| 화재 | 화재유형 | 건축·차량·임야 등 |
| 발화 | 발화열원 대/소, 발화요인 대/소, 최초착화물 대/소 | 원인 조합 |
| 피해 | 인명피해 소계, 사망, 부상, 재산피해 소계 | 대형화 여부(결과 아이템) |

- README가 가정한 변수 중 **건축물 구조·층수, 초기 소화 여부, 경위 텍스트는 이 컬럼 목록에 없다.**

- 소방청 정보공개청구로 원자료를 받을 수 있는지는 **미확인**. 학기 일정 안에 받을 수 있을지가 관건이다.

## 1.2 기상 데이터 (필수)

**프로젝트에서 쓰이는 곳:** 화재 기록에 없는 습도·풍속·기온을 구간화해 아이템으로 붙인다 (예: `실효습도<35%`).

### 1.2.1 ASOS 시간자료 API

- 출처: [data.go.kr 15057210](https://data.go.kr/data/15057210/openapi.do)
- REST, JSON/XML, 무료, 개발계정 10,000건, 전일(D-1)까지 제공 (**확인**)
- 요청: `dataCd=ASOS`, `dateCd=HR`, 시작·종료 일시, `stnIds`(지점번호)
- 요소: 기온, 강수량, 습도, 기압, 풍향, 풍속 등
- 주의: 같은 지점번호라도 기간별로 위치가 다를 수 있음. ASOS는 주요 도시 위주라 시군구별로 가장 가까운 지점에 매핑해야 함.

### 1.2.2 실효습도

- 기상자료개방포털에 지점·일시별 실효습도 조회 화면이 있음 ([data.kma.go.kr 실효습도](https://data.kma.go.kr/climate/ehum/selectEhumChart.do)). 파일 다운로드나 API 제공 여부는 **미확인**.
- 건조특보 기준: 실효습도 35% 이하 2일 이상 예상 시 건조주의보, 25% 이하 2일 이상 예상 시 건조경보 ([기상청 특보 기준](https://www.weather.go.kr/w/forecast/guide/standard.do)). 구간화 경계값으로 쓸 수 있다.
- 계산식: 최근 며칠간 일평균 상대습도를 감쇠계수 r(흔히 0.7로 알려짐)로 가중평균하는 방식으로 알려져 있으나, 공식 문서로는 **미확인**. 포털 값을 그대로 받을 수 있으면 직접 계산할 필요가 없다.

### 1.2.3 결합 조건

- 결합 키: (화재 시군구 → ASOS 지점) + (화재 일시 → 관측 일시)
- 화재 `일시`에 시각이 없으면 일 단위 기상(일평균 습도, 최대풍속 등)만 결합할 수 있다.

## 1.3 건축물 데이터 (선택)

**프로젝트에서 쓰이는 곳:** 노후도(사용승인일), 구조, 층수, 용도 아이템. README의 "노후 다세대" 예시에 필요하다.

- 국토교통부 건축물대장정보 서비스 [data.go.kr 15134735](https://www.data.go.kr/en/data/15134735/openapi.do), 표제부 조회 `getBrTitleInfo` (**확인**: 엔드포인트 경로)
- 표제부 항목: 구조, 용도, 사용승인일, 연면적 등 (제3자 가이드 기준, 공식 응답 필드명은 **미확인**)
- 필수 입력: 시군구코드, 법정동코드, 번, 지 → **건물 단위 지번이 필요하다.**
- **결합 문제:** 공개 화재 데이터의 위치는 시군구까지라 화재 건과 건물을 1:1로 연결할 수 없다.
- 대안(검토 필요): 시군구별 노후 건축물 비율 같은 지역 단위 지표를 아이템으로 쓰는 방식. 다만 개별 화재의 건물 특성이 아니라서 해석이 약해진다.

## 1.4 비정형 텍스트: 경위서·화재조사서 (README상 필수)

**프로젝트에서 쓰이는 곳:** Stage 1에서 Solar가 위험 태그(`#문어발콘센트` 등)를 추출하는 입력.

- 공개 데이터셋에 서술형 컬럼 없음 (1.1의 모든 데이터셋 기준, **확인**)
- NFDS 화재보고서 게시판에 개별 화재조사 보고서 1건(공장 화재)만 확인 ([게시판 B26](https://www.nfds.go.kr/bbs/selectBbsList.do?bbs=B26)). 정기 공개는 **미확인**.
- NFDS 화재사례 게시판(B24)은 열람하지 않음 (**미확인**).

**대안 후보 (팀 결정 필요):**
1. 텍스트 없이 코드형 분류(발화요인 소분류 등)만으로 아이템 구성 → Stage 1의 Solar 역할 축소
2. NFDS 화재사례 게시판·언론 보도 등 공개 사례로 소규모 텍스트 세트 구축 → 표본이 작아 장바구니 전체와는 별도 실험이 됨
3. 정보공개청구로 경위 텍스트 요청 → 개인정보 문제로 제공 여부 불확실, **미확인**

## 1.5 코드표·분류체계 (필수)

**프로젝트에서 쓰이는 곳:** 아이템 사전 설계, 소분류를 묶는 기준, "자명한 규칙" 판단의 근거.

- 화재원인은 발화열원, 발화요인, 최초착화물 세 관점으로 분류됨 (논문 기준, [KoreaScience](https://koreascience.kr/article/JAKO202219957288241.pdf))
- 2007년 개편안: 기존 11종을 발화열원 26종, 발화요인 42종, 최초착화물 57종으로 세분화 제안 ([KFPA 기고](https://kfpa.or.kr/mem/pdf_file/H/117/H117_7.pdf)). 현행 기준과 같은지는 **미확인**.
- 근거 규정: 화재조사 및 보고규정 (2011년 논문은 내부 훈령으로 설명). 현행 명칭과 코드표 원문은 **미확인**.
- 실무적 대안: CSV를 받으면 대/소분류 값의 고유값 목록을 뽑아 코드표를 직접 만들 수 있다. 화재통계연감 PDF로 분류 정의를 보완한다.

## 1.6 수집 우선순위

1. **1.1.1 연간화재통계 CSV 확보** → 행 수, 기간, `일시` 형식 확인 (모든 결정의 전제)
2. **1.5 코드표 정리** → CSV 고유값 + 연감 PDF
3. **1.2 기상 데이터** → `일시` 형식에 따라 시간/일 단위 결정, 실효습도 다운로드 가능 여부 확인
4. **1.4 텍스트 대안 결정** → 팀 논의
5. **1.3 건축물** → 1.4와 함께 범위 결정 후 필요 시
